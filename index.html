Flagship · launched April 2026

Packleads

A local business intelligence platform that measures how visible a business really is, then turns the gaps into a report you can hand a client.

1,200 leads in 12 weeks · 4,478 businesses · 18,792 US cities · 7,197 review snapshots

packleads.io

Problem, build, result

Problem

Before engineering I was a web designer, and finding clients was the hardest part of the job. I spent nights scrolling Google Maps guessing which local businesses had weak websites and which were worth pitching. I was the customer before I was the founder.

Build

Next.js 14 and TypeScript on Supabase with row level security, Redis on Upstash for caching and rate limiting, Stripe for credit based billing. Natural language search runs a plain English brief through an OpenAI query planner, which compiles it into a structured query against live business data. A registry of 19 analyzers runs over a single crawl and produces a 0 to 100 visibility score. Adding a signal is one registry entry, not another pass over the data.

Result

1,200 leads processed in the first twelve weeks. 4,478 businesses measured across 18,792 US cities, with 7,197 review snapshots collected over time, which is data you can only build by watching rather than looking up.

Next.js · TypeScript · React · Tailwind · Supabase · PostgreSQL · Redis · Stripe · OpenAI · Leaflet · Playwright · Vercel

  1. Sellorie AI voice automation that answers the restaurant phone when nobody on the floor can. Product · 2025

    Problem

    I was a regular at the restaurant, so I interviewed the floor staff about what actually blocked them before I ever spoke to management. By the time I sat down with the manager I already knew the answer. During peak hours nobody could pick up the phone, call in orders were being lost, and hiring someone to answer it was not affordable.

    Build

    Next.js and TypeScript front end over distributed middleware that routes transactions between the voice engine, n8n automation, Clover POS, and Stripe, with webhook handling and monitoring across all three. The voice layer is a custom interaction engine on ElevenLabs, tuned for multi turn calls that hold context the way a person does.

    Result

    Ran in real restaurants taking real orders, not a demo. The first customer led to introductions across other sectors. I owned it from architecture through delivery.

    Next.js · TypeScript · ElevenLabs · Clover POS · Stripe · n8n · Webhooks · REST

  2. Global Report Builder One reporting surface across every plant, so sites stopped reporting in their own private dialect. Oshkosh · 2024 · 100+ users

    Problem

    Every facility built its own reports its own way, so nothing rolled up and no two sites could be compared without someone rebuilding the numbers by hand.

    Build

    A Vue.js front end over Python services running on Ignition Perspective and WebDev, pulling live data across factory floors through MQTT and OPC-UA. Authentication, data filtering, and scheduled exports are configured in the gateway so operations owns them rather than filing a ticket.

    Result

    Delivered to more than 100 people across global operations, and site reporting became one format instead of a dozen.

    Vue.js · Python · Ignition Perspective · Ignition WebDev · MQTT · OPC-UA · SQL

  3. Serial number recognition Cameras that read stamped, etched, and handwritten serial numbers off equipment while the line keeps moving. Oshkosh · 2022 to 2024 · 98% accuracy

    Problem

    Serial capture was manual. Someone read a number off a part and typed it in, which is slow at best and quietly wrong at worst.

    Build

    A TensorFlow model trained and deployed on Azure ML, using CNNs and OCR with OpenCV to handle low contrast, glare, and stamped metal. It surfaces inside an Ignition Perspective workstation, so operators use it where they already work instead of learning a second tool.

    Result

    98% accuracy across three production lines, and the pipeline scaled to multiple sites.

    Python · TensorFlow · Azure ML · Azure AI · OpenCV · OCR · Ignition Perspective

  4. PulseHue Room lighting that follows what is playing, without a round trip through a vendor cloud. Personal · 2025 · 700ms end to end

    Problem

    Every ambient lighting integration I could find sent commands through a vendor cloud, which meant the lights were always a beat behind the music.

    Build

    A Node.js and Express service reading live Spotify playback over OAuth 2.0 and driving Govee lights directly over the LAN. Dominant color extraction from album art with HSL to RGB mapping picks the scene. Lights that are powered off or drop off the network are retried rather than allowed to wedge the loop.

    Result

    About 700ms from a track change to a light change, and the remaining latency is Spotify polling rather than anything on the device path.

    Node.js · Express · Spotify Web API · OAuth 2.0 · Govee LAN API · REST

  5. Client web builds Production websites built against a defined system rather than page by page. Independent · 2024 to present

One incident, if you only read one thing

Two sensors on the autonomous guided vehicle fleet stopped reporting telemetry, and the loss was silent. The vehicles kept running. What broke was station control no longer registering when a vehicle arrived, so it surfaced as station logic misbehaving rather than as missing data. Root cause was a tag rename shipped in a firmware and configuration change, which left the subscriber bound to a path that no longer existed, so two feeds went quiet without ever raising an error. I re-pointed the subscription, added staleness alerting so a feed that stops publishing pages someone instead of going unnoticed, and wrote the postmortem.

● Approach Why I build the way I do
Software that matters is software somebody is depending on right now.

Where it starts

I grew up in the Democratic Republic of the Congo until I was seven, without much access to technology. Getting to it late is why building for the web has never stopped feeling like something worth being careful about. I do not take a working system for granted, because I remember not having one.

Who it is for

The people using what I build at work are plant operators and maintenance technicians, reading a screen mid shift with a line waiting on them. Watching someone depend on your interface under pressure permanently changes how you think about a loading state, an error message, and where the important number goes.

How I find problems

By being in them. Packleads exists because I was the web designer scrolling maps for leads. Sellorie exists because I asked the floor staff what was breaking before I asked the manager. The constraint is rarely headcount, it is the money to hire the headcount, and you only learn that by talking to the people doing the work.

What I hold to

If I built it, I stand behind it. That means writing the runbook as well as the service, adding the alert after the incident, and telling you plainly what I have not done yet. Overselling gets found out in week two, and I would rather be the person you keep calling.
